# Production Runbook

## Required Services

- Managed PostgreSQL 16 with pgvector enabled
- Managed Redis 7+ or an equivalent Redis-compatible service
- TLS/mTLS terminating reverse proxy using the NPCI client CA
- Immutable audit destination such as S3 Object Lock, Azure immutable blob, or WORM storage
- Metrics scraper such as Prometheus
- Secret manager or orchestrator secret mounts for all sensitive values

## Required Environment

Set these before starting the API:

```env
APP_ENV=production
AUTH_COOKIE_SECURE=true
DATABASE_URL=<managed-postgres-url>
REDIS_URL=<redis-url>
SECRET_KEY=<64+ char random secret>
A2A_HMAC_SECRET=<64+ char shared secret>
NPCI_API_KEY=<32+ char secret>
A2A_MTLS_REQUIRED=true
A2A_JWT_REQUIRED_EXTERNAL=true
A2A_CIDR_ALLOWLIST=<npci-cidr-list>
A2A_MTLS_FINGERPRINTS=<proxy-native-or-sha256-client-cert-fingerprints>
A2A_MTLS_PARTNER_MAP=<proxy-native-or-sha256-fingerprint>=<partner-id>
A2A_JWT_PARTNER_MAP=<jwt-sub>=<partner-id>
A2A_KNOWN_AGENTS=<partner-id-list>
NPCI_AGENT_URL=https://<npci-agent-host>/a2a
NPCI_CLIENT_CERT_FILE=/run/secrets/npci_client_cert
NPCI_CLIENT_KEY_FILE=/run/secrets/npci_client_key
A2A_INGESTION_MODE=worker
CORS_ORIGINS=https://<admin-console-host>
METRICS_BEARER_TOKEN=<random-prometheus-scrape-token>
CHAT_MAX_REQUEST_BYTES=65536
SHUTDOWN_GRACE_SECONDS=30
```

Secret-manager file mounts are also supported with `SECRET_KEY_FILE`,
`A2A_HMAC_SECRET_FILE`, `NPCI_API_KEY_FILE`, `GOOGLE_API_KEY_FILE`,
`DATABASE_URL_FILE`, `REDIS_URL_FILE`, and `METRICS_BEARER_TOKEN_FILE`.
Outbound NPCI mTLS uses mounted certificate/key paths via
`NPCI_CLIENT_CERT_FILE` and `NPCI_CLIENT_KEY_FILE`.

Use `.env.production.example` as the deployment template. Do not commit
`.env.production`; it is ignored by git and should be generated by your
deployment pipeline or secret manager.

## Container Deployment

`docker-compose.prod.yml` defines the production process topology:

- `migrate`: one-shot `alembic upgrade head`
- `api`: FastAPI served by Gunicorn with multiple Uvicorn workers
- `worker`: separate `python worker.py` ingestion worker
- `reverse-proxy`: Nginx TLS/mTLS termination
- `prometheus`: authenticated scraping and alert rule evaluation
- `alertmanager`: alert routing

Before starting the stack, provide:

```env
TLS_CERT_DIR=/secure/certs/nginx
PROMETHEUS_CERT_DIR=/secure/certs/prometheus
SECRET_KEY_FILE_HOST=/secure/secrets/secret_key
DATABASE_URL_FILE_HOST=/secure/secrets/database_url
REDIS_URL_FILE_HOST=/secure/secrets/redis_url
GOOGLE_API_KEY_FILE_HOST=/secure/secrets/google_api_key
NPCI_API_KEY_FILE_HOST=/secure/secrets/npci_api_key
A2A_HMAC_SECRET_FILE_HOST=/secure/secrets/a2a_hmac_secret
METRICS_BEARER_TOKEN_FILE_HOST=/secure/secrets/metrics_bearer_token
SMTP_PASS_FILE_HOST=/secure/secrets/smtp_pass
```

The Nginx cert directory must contain:

- `tls.crt`
- `tls.key`
- `npci_ca.crt`

The Prometheus cert directory must contain:

- `tls_ca.crt`

Start or update:

```powershell
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
```

The compose stack intentionally does not create PostgreSQL or Redis containers.
Point `DATABASE_URL` and `REDIS_URL` at managed private-network services.

## Deployment Order

1. Install dependencies:

```powershell
pip install -r requirements.txt
```

2. Apply schema migrations:

```powershell
alembic upgrade head
```

3. Start the API:

```powershell
gunicorn main:app --worker-class uvicorn.workers.UvicornWorker --workers 4 --bind 0.0.0.0:8000
```

4. Start at least one ingestion worker:

```powershell
python worker.py
```

5. Configure the reverse proxy:

- Enforce TLS.
- Validate NPCI client certificates.
- Forward `X-SSL-Client-Verify` and `X-SSL-Client-Fingerprint`.
- Apply request-size limits for uploads and A2A bodies.
- Keep PostgreSQL and Redis private.

When using the compose stack, step 2 is handled by the `migrate` service and
steps 3-4 are handled by the `api` and `worker` services. The app still refuses
production startup if the database is not at Alembic head.

## Monitoring

Scrape:

```text
GET /metrics
```

The repo includes `deploy/prometheus/prometheus.yml` and
`deploy/prometheus/alert_rules.yml` for baseline scraping and alerting.
Prometheus must send `Authorization: Bearer <METRICS_BEARER_TOKEN>`.

Alert on:

- `login_failures_total`
- `rate_limit_rejections_total`
- `a2a_auth_rejections_total`
- elevated `http_request_duration_seconds`
- worker process exits
- ingestion jobs stuck in `queued`, `processing`, `extracting`, or `embedding`
- audit export failures

## Backup And Restore

Take encrypted PostgreSQL backups at least daily and before every production
migration. Retain point-in-time recovery logs according to the NPCI audit and
bank retention policy. Store backups outside the application host in immutable
or access-controlled storage.

Minimum backup command:

```powershell
pg_dump --format=custom --no-owner --file mindgate_$(Get-Date -Format yyyyMMdd_HHmmss).dump $env:DATABASE_URL
```

Minimum restore drill:

```powershell
createdb mindgate_restore_drill
pg_restore --dbname mindgate_restore_drill --clean --if-exists .\mindgate_<timestamp>.dump
alembic upgrade head
python audit_export.py verify
```

Run restore drills monthly and after schema changes. Verify vector indexes,
audit hash-chain continuity, A2A idempotency rows, and admin login before
declaring the drill successful.

## Audit Export

Verify the hash chain:

```powershell
python audit_export.py verify
```

Export audit artifacts:

```powershell
python audit_export.py export --out audit_exports
```

Move the exported files and manifest to immutable storage immediately after
export. Keep the manifest hash with the storage object metadata.

See `deploy/audit/README.md` for the immutable-storage operating pattern.
