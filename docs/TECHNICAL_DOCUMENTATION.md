# Mindgate Partner Platform — Technical Documentation

> **Status:** current implementation (repository root, flat-module layout).
> **Version:** app `2.0.0`.
> This document is the authoritative technical reference for the system as it
> exists in the codebase today. Where older docs describe a "vanilla-JS RAG
> chatbot," they predate the current build — the app is now a **React SPA
> Partner Platform** fronting a FastAPI backend that combines a grounded RAG
> assistant with a conformant **NPCI A2A (Agent-to-Agent) protocol** surface.

---

## 1. What the system is

The Mindgate Partner Platform is the **Bank-side** software that a partner bank
(Mindgate's customer) runs to participate in NPCI's *Unified AgentNxt A2A
Protocol*. It does two related jobs:

1. **RAG policy assistant.** Staff ask natural-language questions about internal
   policy and NPCI circulars; answers are generated by Google Gemini strictly
   grounded in ingested documents (PostgreSQL + pgvector retrieval), streamed
   token-by-token to the browser.

2. **A2A change-lifecycle agent.** It exchanges structured JSON messages with
   NPCI's platform to drive a *change* (a mandated product/spec change) through
   its lifecycle — receiving change communications and product kits, asking
   clarifying queries, submitting counter-proposals, reporting milestones,
   raising blockers, and declaring readiness for certification.

The two halves connect: documents that arrive over A2A (NPCI circulars, tech
specs, FAQs) are auto-ingested into the same RAG knowledge base the assistant
answers from, and low-confidence assistant queries can be escalated to NPCI as
formal A2A `query` messages.

### Scope boundary

This codebase implements **only the Bank's responsibilities**. NPCI's platform /
certification-simulator side is out of scope and is stubbed for local testing by
`mock_npci_agent/`. Conformance is judged on Bank-side behavior only.

### Two user personas

| Persona | Role | Lands on | Can access |
| --- | --- | --- | --- |
| **Admin** | Platform operator | Incoming Changes board (`/`) | Everything: changes board, settings, users, knowledge base, assistant |
| **Bank Product Manager (PM)** | Non-admin owner of a change | Personal dashboard (`/dashboard`) | Their assigned changes, change detail, knowledge base, assistant |

## 4. Application bootstrap & middleware

`main.py` wires the whole app. On import it loads `.env`, resolves `*_FILE`
secrets, and constructs the Gemini client. The FastAPI app uses a **lifespan**
context that:

1. Runs `_validate_security_config()` — fails fast on unsafe production settings
   (weak `SECRET_KEY`/`A2A_HMAC_SECRET`/`NPCI_API_KEY`, wildcard CORS, missing
   mTLS/CIDR/partner maps, non-worker ingestion mode, missing Redis, etc.).
2. Sizes the default thread-pool executor to 40 workers (kept below the DB pool
   ceiling of 50) so `asyncio.to_thread` can service concurrent blocking Gemini
   and DB calls without pool-timeout.
3. In production, asserts the DB is at the **expected Alembic revision**
   (`_assert_database_migrated`); in dev, calls `init_db()` to create tables,
   the pgvector extension, and the HNSW index.
4. Recovers durable A2A state left by an unclean shutdown (received changes,
   orphaned ingestion jobs).
5. Starts a periodic background task that deletes expired HMAC nonces / WS
   tickets and times out stale idempotency claims.

### Middleware stack (order matters)

- **CORS** — explicit origins from `CORS_ORIGINS` (never wildcard with
  credentials); methods and headers are enumerated, not `*`.
- **CSRF** — `csrf_middleware` validates Origin/Referer on cookie-authenticated
  mutating requests. Registered *after* CORS so preflight is handled first.
- **Security headers** — every response gets a per-request `X-Request-ID`, a
  strict **Content-Security-Policy with a per-request nonce**, `X-Frame-Options:
  DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
  `Permissions-Policy`, and HSTS on HTTPS. This middleware also enforces a body
  size cap on `/chat` and `/chat/stream` and records Prometheus request
  counters/histograms.

### CSP nonce injection

Because the CSP forbids inline scripts/styles without a nonce, the SPA's
`index.html` is served through `_inject_csp_nonce()`, a regex that stamps the
per-request nonce onto every `<script>`/`<style>` tag that lacks one. Hashed
Vite assets are mounted at `/assets`; browser navigation under `/` and
`/admin/*` returns the SPA shell.

## 5. Data model

All tables are SQLAlchemy models in `database.py`. Grouped by concern:

### RAG / documents

- **`document_chunks`** — chunk `text` + `embedding` (`Vector(dim)`), with
  `source_file`, `chunk_index` (unique together), `source`, `visibility_tier`,
  `page_number`, `content_type`, `document_id` FK, and NPCI-linkage fields
  (`change_id`, `ticket_id`, `source_doc`, `citations_json`, `provisional`).
  HNSW cosine index on `embedding`.
- **`received_documents`** — an inbound A2A document with `content_hash`
  (SHA-256, **unique** → dedup), `stored_path`, `status` lifecycle, `source`,
  `change_id`, `doc_type`, `version`.
- **`a2a_ingestion_jobs`** — async job per received document (`status`, `error`,
  timing), cascade-deleted with its document.
- **`document_summaries`** — per-document generated summary.

### Chat

- **`users`** — account with `email`, optional portal `username`,
  `hashed_password`, `is_admin`, `is_active`, MFA (`mfa_enabled`,
  `totp_secret`), and `visibility_tier`.
- **`chat_sessions`** — UUID id, owned by a user (cascade delete).
- **`chat_messages`** — `role` (`user`/`assistant`) + `content`, ordered.
- **`message_feedback`** — one rating per assistant message (legacy surface).
- **`voice_notes`** — admin-saved knowledge-base text notes.

### A2A protocol & change lifecycle

- **`a2a_changes`** — lifecycle state of an NPCI change (`current_state`,
  `version`, `partner_id`, `owner_user_id`, blocked/deleted markers). The
  `owner_user_id` scopes NPCI updates for a change to a single PM's dashboard.
- **`a2a_cflows`** — certification-flow lifecycle state (Part B, out of scope but
  modeled).
- **`npci_tickets`** — escalation tickets and their `clarification_response`
  fields (`interpretation_confirmed`, `grounded_in`, `amends_change`, etc.).
- **`a2a_counter_proposals`** — Bank→NPCI counters and NPCI's per-clause decision.
- **`a2a_blockers`** — Bank→NPCI blockers plus NPCI status/resolution.
- **`a2a_milestones`** — latest per-milestone state (design/coding/testing).
- **`hidden_updates`** — portal feed items an admin has hidden from PM dashboards.
- **`app_settings`** — runtime-editable config surfaced in the Settings page;
  secrets flagged `is_secret` and never echoed in plaintext.

### Security / audit

- **`a2a_messages`** — audit row for **every** inbound/outbound A2A message,
  accepted or rejected (with `error_code`). **Append-only, hash-chained.**
- **`a2a_idempotency_keys`** — mutable pre-processing concurrency gate
  (transport `message_id` + business key) that prevents duplicate side effects.
- **`a2a_nonces`** — HMAC replay-detection nonce store (Postgres fallback for
  Redis), TTL-expired.
- **`audit_logs`** — admin actions (upload/delete/etc). **Append-only,
  hash-chained.**
- **`revoked_sessions`** — JWT `jti` denylist for logout / forced revocation.
- **`ws_tickets`** — short-lived single-use WebSocket auth tickets.

### Tamper-evident audit chain

`audit_logs` and `a2a_messages` are protected two ways:

1. **ORM `before_insert` hooks** compute `entry_hash = sha256(prev_hash + canonical_row)`,
   forming a hash chain under a Postgres advisory lock (serialized ordering).
2. **`before_update`/`before_delete` are rejected** at the ORM layer *and* by a
   database trigger (`prevent_audit_mutation`), so records cannot be altered or
   removed even outside the ORM. `audit_export.py` can re-verify the chain.

## 6. RAG subsystem

### 6.1 Ingestion pipeline (`ingest.py`, `services/a2a_ingestor.py`)

```
PDF/file → PyMuPDF text extraction
        → (optional) Gemini vision over rendered pages (USE_VISION)
        → overlapping semantic chunking (~800 tok, ~100 overlap)
        → sanitize suspicious in-document instructions
        → gemini-embedding-001 (retry + backoff, throttled)
        → replace prior chunks for the same source / skip duplicate content_hash
        → insert chunks + vectors into PostgreSQL
```

Ingestion is triggered by: CLI (`python ingest.py`), authenticated `POST
/ingest`, admin upload, the Watchdog file watcher (debounced, bounded sequential
queue), or an inbound A2A `change_communication` / document message.

For A2A documents the entry point is asynchronous: the route stores the original
file under `data/a2a_received/`, computes `content_hash = sha256(bytes)`, writes
`received_documents` + `a2a_ingestion_jobs` rows, returns a `job_id`, and a
background worker does extraction → chunk → embed → summarize → notify. Duplicate
hashes are never re-ingested. Failed jobs are retryable via
`POST /ingestion-jobs/{job_id}/retry`. Lifecycle status:
`queued → processing → extracting → embedding → ready | failed`.

### 6.2 Retrieval (`retriever.py`)

The question is embedded with the same model used at ingestion, compared via the
pgvector cosine operator `<=>` over an HNSW index, and the top-K chunks are
returned. A light source-priority rerank favors authoritative sources
(`npci_official > npci_agent > admin_upload > old_policy`).

Confidence is derived from distance:

```
confidence = max(0.0, 1.0 - (best_distance / A2A_EMBEDDING_SCALE))
```

If confidence is below `A2A_CONFIDENCE_THRESHOLD`, `/chat/stream` emits a
`low_confidence` SSE event, **skips Gemini generation**, and surfaces the "Raise
to NPCI" action instead of guessing.

### 6.3 Grounded generation & prompt (`prompt.py`)

Retrieved chunks are labeled `[Chunk N]` and injected as the only allowed
context. The system prompt instructs the model to answer strictly from context,
never invent clauses or citations, flag contradictions rather than resolve them
silently, and remain an informational assistant (not an approver or legal
authority). Up to 5 recent user/assistant pairs are included as memory
(sanitized to reduce memory-poisoning).

### 6.4 Guardrails (`guardrails.py`) — defense in depth

| Tier | Mechanism | Catches |
| --- | --- | --- |
| **1** | Precompiled regex fast-path (zero cost) | Obvious "ignore instructions", prompt-extraction, raw-chunk dumps, role-play, forced yes/no |
| **2** | Gemini semantic intent classifier | Paraphrased / indirect / novel-phrasing attacks by **intent** |
| **3** | Output guard (post-generation) | System-prompt fragments, rule leakage, bulk chunk reproduction → replaced with safe fallback |

Additional helpers: `sanitize_question()` strips embedded meta-instructions from
queries; `sanitize_chunk()` neutralizes injection inside ingested document text;
`VerifiedStreamBuffer` buffers streamed output so the backend can emit a final
`replace` event to overwrite already-streamed unsafe content. The Tier-2
classifier is wrapped in a **circuit breaker** so classifier outages degrade
gracefully rather than blocking all chat.

### 6.5 Streaming (`/chat/stream`)

Gemini's blocking stream iterator runs in an executor thread that pushes
`("token"|"error"|"done", ...)` events onto an `asyncio.Queue`; an async SSE
generator drains the queue and yields JSON events. The guardrail check and
vector retrieval run concurrently via `asyncio.gather`. Anti-buffering headers
(`Cache-Control: no-transform`, `X-Accel-Buffering: no`) keep proxies from
holding the stream. The React client reads `response.body`, decodes SSE frames,
and reveals text at animation-frame cadence.

## 7. A2A protocol subsystem

The A2A surface is the system's defining feature. It is modeled on the **NPCI
Unified AgentNxt A2A Protocol v1.0** (`a2a_models.py`).

### 7.1 Two endpoints, two trust levels

| Endpoint | Auth | Dispatch | Callers |
| --- | --- | --- | --- |
| `POST /a2a/external` | 8-layer chain (HMAC + mTLS + JWT …) | `agent/external_dispatcher.py` on `task_type` | NPCI platform / mock agent |
| `POST /a2a/internal` | Admin/PM JWT | `agent/dispatcher.py` on JSON-RPC `method` | The portal SPA |

`POST /a2a` is deprecated and returns `410 Gone` — it previously mixed trust
levels and was split for isolation.

### 7.2 The envelope (spec §4)

Every message wraps a common envelope: `task_type`, `change_id`/`cflow_id`,
`from`/`agent_id`/`agent_run_id`, `correlation_id`, `timestamp` (ISO-8601 UTC),
`protocol_version` (`"1.0"`), `message_id` (transport idempotency key), and a
`payload` dict validated against a per-task Pydantic model.

### 7.3 Task types (spec §6)

**Part A — Change lifecycle (Phase C), 14 messages, in scope:**
`change_communication`, `proposal_acknowledged`, `change_acknowledgement`,
`query`, `clarification_response`, `counter_proposal`, `counter_decision`,
`milestone_update`, `milestone_status_request`, `milestone_status_report`,
`readiness_declaration`, `blocker`, `blocker_status_update`, `blocker_resolution`
(plus `echo` connectivity test).

In the external dispatcher, **inbound NPCI→Bank messages do real work** (persist
state, advance the change state machine, ingest product-kit documents), while
**Bank-originated types are validate-and-ack on loopback**. Certification (Part
B, `cert_*`) task types are modeled but return `not_implemented`.

### 7.4 The 8-layer external auth chain (`a2a_auth.py`)

`a2a_external_auth` is a FastAPI dependency on `/a2a/external`. Each layer
short-circuits with the exact spec error-code string (so NPCI SOC tooling and
local monitoring can pattern-match failures):

1. **mTLS** — reverse-proxy client-cert fingerprint → `mtls_required` / `mtls_fingerprint_mismatch`
2. **CIDR allowlist** → `ip_not_allowed`
3. **HMAC envelope** — signature + timestamp skew + nonce replay → `signature_mismatch` / `timestamp_skew` / `replay_detected` / `missing_envelope_headers`
4. **JWT + session** → `invalid_token` / `session_revoked` / `session_expired`
5. **Partner status** → `partner_inactive`
6. **change_id/cflow_id ownership** → `partner_mismatch` / `unknown_id`
7. **State-machine validity** → `invalid_state_transition`
8. **Agent identity** → `unknown_agent` / `agent_not_authorized_for_task`

mTLS and JWT-required enforcement are gated to production so the plain-HTTP mock
agent works locally. Partner/agent/fingerprint bindings come from env maps
(`A2A_MTLS_PARTNER_MAP`, `A2A_JWT_PARTNER_MAP`, `A2A_KNOWN_AGENTS`, …).

### 7.5 Idempotency & audit (`a2a_audit.py`, `a2a_state.py`)

Each external handler is wrapped: **claim idempotency key** (transport
`message_id` + business key) → execute handler → advance state on success →
**audit-log** the message (success or failure) into the append-only
`a2a_messages` chain. Duplicate requests short-circuit to the cached result
instead of re-running side effects. Stale `processing` claims are timed out by
the periodic cleanup task.

### 7.6 Internal JSON-RPC methods (`agent/methods.py`)

Used only on `/a2a/internal` (admin/PM JWT):

- `agent.get_summary`, `agent.query_rag`, `agent.escalate_to_npci`
- Outbound Bank→NPCI portal actions: `agent.submit_counter_proposal`,
  `agent.report_milestone`, `agent.declare_readiness`, `agent.raise_blocker`

Outbound dispatch to NPCI is built in `services/npci_outbound.py` /
`services/npci_client.py` (mutual-TLS client in production).

## 8. Authentication & authorization

- **Passwords** (`auth.py`) — bcrypt, but every password is SHA-256+base64
  pre-hashed first so passphrases over bcrypt's 72-byte ceiling keep full
  entropy. A password policy is enforced at registration.
- **JWT** — HS256 (`SECRET_KEY`) or RS256 (`AUTH_PRIVATE_KEY`/`AUTH_PUBLIC_KEY`
  if both set). Short default lifetime (**15 min**); each token carries a `jti`.
- **Sessions & revocation** — logout / forced revocation add the `jti` to
  `revoked_sessions`; `get_current_user` rejects revoked/expired tokens.
  `POST /auth/refresh` issues fresh tokens.
- **Browser sessions** — `/auth/admin/login` and `/auth/login/session` set an
  **HttpOnly, SameSite=strict** cookie (`mg_access_token`); Bearer tokens are
  still returned for non-browser clients. `/auth/me` restores the SPA session;
  `/auth/logout` clears the cookie.
- **MFA** — TOTP via `pyotp`: `/auth/mfa/setup` → `/auth/mfa/enable` →
  `/auth/mfa/verify` (step-up during login when `mfa_enabled`).
- **Roles** — `get_current_user` and `get_current_admin` dependencies gate
  routes; the SPA additionally route-gates admin-only pages. Admin cannot be
  self-granted at registration — it is a trusted DB/admin operation.

## 9. Security posture (summary)

| Control | Where |
| --- | --- |
| Strict CSP w/ per-request nonce, no inline JS/CSS | `security_headers_middleware`, `_inject_csp_nonce` |
| CSRF Origin/Referer validation on cookie routes | `csrf.py` |
| Rate limiting on sensitive endpoints | `rate_limit.py` |
| Fail-fast unsafe-config validation | `main._validate_security_config` |
| Upload validation (magic bytes, size, extension) | `file_validation.py` |
| External-AI data-processing approval gate | `compliance.py` |
| Prompt-injection defense (3 tiers) + sanitizers | `guardrails.py` |
| Append-only hash-chained audit for admin + A2A | `database.py` hooks + triggers |
| Notify-list allowlisting (no arbitrary outbound email) | `A2A_NOTIFY_*` + `email_notify.py` |
| Secrets from files, never source | `secrets_loader.py`, `*_FILE` envs |
| mTLS in/out, CIDR allowlist, HMAC replay protection | `a2a_auth.py`, Nginx |

Inbound NPCI reply auto-ingestion is opt-in (`NPCI_REPLY_AUTO_INGEST`); when off,
replies are stored `pending_review` for admin approval before becoming RAG
knowledge.

## 12. Background processing & reliability

- **Ingestion worker** (`worker.py`) — in production, ingestion runs
  out-of-process (`A2A_INGESTION_MODE=worker`) so heavy embedding work never
  blocks the API. `services/task_queue.py` abstracts the queue.
- **File watcher** — Watchdog monitors `data/`, debounces (5s), and feeds a
  bounded (≤50) sequential queue; one daemon worker ingests to avoid Gemini
  quota bursts. Admin uploads suppress duplicate watcher events.
- **Crash recovery** — on startup, `recover_received_changes()` and
  `recover_orphaned_jobs()` re-drive A2A state and ingestion jobs interrupted by
  an unclean shutdown; stale idempotency claims are timed out.
- **Retention** (`services/retention.py`) — data purge / retention jobs.
- **LLM resilience** — retry with backoff on transient errors, then automatic
  model fallback (`gemini_models()`); the guardrail classifier has a circuit
  breaker.

## 15. Deployment

- **Local** — `docker-compose.yml` starts PostgreSQL+pgvector; `start.ps1`
  waits for the DB and launches Uvicorn. The React app builds to `frontend/dist`
  (or run `npm run dev` for hot reload).
- **Image** — multi-stage Dockerfile: a `node:20` stage builds the SPA, then the
  Python runtime image copies `dist/` in — no manual frontend build for
  containers.
- **Production** — `docker-compose.prod.yml`: managed PostgreSQL + Redis,
  file-mounted secrets, Alembic migrations as a one-shot service, a separate
  ingestion worker, Nginx terminating TLS/mTLS, and Prometheus scraping. Startup
  refuses to run unless `alembic upgrade head` has been applied to the expected
  revision. Kubernetes manifests live in `deploy/k8s/`. See
  `docs/PRODUCTION_RUNBOOK.md` for the full sequence.

## 17. Known boundaries & limitations

- **NPCI side is out of scope** — only Bank responsibilities are implemented;
  the NPCI counterpart is simulated by `mock_npci_agent/` for end-to-end tests.
- **Certification (Part B)** — task types are modeled but return
  `not_implemented`; only Part A (change lifecycle) does real work.
- **Bank-originated A2A types** are validate-and-ack on loopback rather than
  fully round-tripped against a real NPCI platform.
- **task_type vocabulary** predates spec v1.0 in places; treat the enum as the
  source of truth for what is actually handled.
- Legacy surfaces remain for compatibility (`/feedback/*`, `/auth/login`,
  voice notes, `message_feedback`) and are not part of the active portal UX.
